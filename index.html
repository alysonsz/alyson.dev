DECISÕES DE ENGENHARIA

O que acontece quando algo falha?

01 / PAGAMENTOS

Retentar sem cobrar duas vezes.

O checkout Stripe recebe uma chave de idempotência por usuário e requisição. Uma repetição do mesmo pedido reutiliza a chave, reduzindo o risco de criar sessões duplicadas após timeout ou falha de rede.

A garantia depende de preservar o identificador da operação entre tentativas.

02 / AGENTES DE IA

Uma resposta não é autorização para repetir uma ação.

Um registro de execução associa ferramentas a chaves de idempotência e persiste seu estado. Uma restrição de unicidade no PostgreSQL trata a disputa entre tentativas concorrentes e impede iniciar novamente a mesma execução.

O registro torna a execução rastreável; concorrência e recuperação continuam sendo responsabilidades do fluxo executor.

03 / WEB E MOBILE

Compartilhar regras tem um custo operacional.

A aplicação web usa uma camada BFF e o mobile acessa o mesmo domínio de negócio no backend. Isso centraliza regras e dados, mas mantém a API como dependência comum dos dois canais.

Evolução proposta: separar capacidade por canal, limitar concorrência e avaliar réplicas de leitura. Réplicas exigem lidar com atraso de leitura; separar servidores, sozinho, não elimina falhas compartilhadas.

CASE 002 / MOBILE + APIEm desenvolvimento

Assistente pessoal

Oria

Uma agente que conecta agenda, tarefas e contexto diário, com confirmação humana antes de alterar compromissos.

Expo / React Native→API .NET→PostgreSQL + OpenRouter
Decisões de arquitetura
  • Domain e Application isolam regras e casos de uso; Infrastructure implementa persistência, autenticação e integração com IA.
  • O calendário é lido no aparelho com escopo de 14 dias para cada lado. Nomes de eventos não são compartilhados por padrão.
  • Chaves ficam no servidor. O chat usa limites de tempo, retentativas para falhas transitórias e fallback controlado entre modelos.

CASE 003 / WEB + APIEm desenvolvimento

Workspace de IA

Nexo

Conversas com seleção de modelos orientada por classificação e custo, em uma interface web com respostas em streaming.

Next.js→API .NET→PostgreSQL + OpenRouter
Decisões de arquitetura
  • Classificação e roteamento ficam na camada Application; um catálogo configurável no backend é a fonte única de modelos.
  • A API envia eventos NDJSON de rota, conteúdo e conclusão, permitindo mostrar a resposta conforme ela chega.
  • Biblioteca e preferências são separadas por sessão em cookie HttpOnly; o frontend não guarda chaves no localStorage.
